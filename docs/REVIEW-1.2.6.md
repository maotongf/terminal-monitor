# Terminal Monitor 1.2.6 检查与优化建议

检查日期：2026-11-18。范围：全部 src 模块、Webview 脚本、样式模板、配置、README、打包流程。此次是代码审查与模拟边界验证，没有修改运行代码、安装新版或重载窗口；未进行真实 VS Code 窗口视觉验收、压力测试或跨平台验收。

当前基础可用：Codex 状态与终端命令状态分开读取；Webview 对动态文本做了转义，使用 CSP；悬浮可停留；大分组可折叠；点击跳转已在用户当前场景中确认工作。下面的问题不代表当前所有任务都受到影响，但应在继续扩展功能之前处理。

## 显示与交互

1. **顶部数字统一含义。** resources/dashboard.js:164 顶部 Active 不包含 quiet，底部 :189 却把 quiet 算进 active。同一个界面会出现两个不同的 active 数。Failed 来自保留历史，缺少统计范围，而且可能与 Codex 历史重复。建议顶部“进行中 / 等待你 / 异常”，终端 Quiet 仅作为该行的辅助状态。等待外部工具不能直接算作“等待你”，需要后端保留等待原因。
2. **语言统一。** 主列表和分组是英文，悬浮是中文，HTML lang=en。当前用户场景建议统一中文，并为后续本地化保留文案字典。
3. **减少重复。** 卡片已经有“已完成”，无需再写“任务已完成”；列表已有目录，悬浮保留一条低对比度短路径即可。只有异常、需要用户操作和实际新内容值得额外强调。
4. **悬浮保留阅读位置。** resources/dashboard.js:168 每次数据变化都会 replaceChildren 重建全部行；:102 会重新写入整个悬浮卡片。代码虽恢复悬浮对象，但没有恢复键盘焦点、文本选择和滚动位置。建议按任务 ID 更新有变化的字段，悬浮保持独立节点，数据更新不打断阅读。
5. **悬浮时间会停住。** 每秒计时器只更新列表 .duration；卡片内耗时和“几秒前”只是生成时的静态文本，若数据没有变化就不会更新。建议为可见卡片单独更新时钟字段。
6. **折叠状态持久化。** collapsedSections 只在内存，重载后丢失。使用 Webview getState/setState 保存分组开合；仍然只折叠大分组，保持用户已确认的设计。
7. **键盘支持不完整。** 行是 tabindex=0 的 div，只有 click，没有 Enter/Space 激活、按钮语义或 aria-describedby。可以聚焦却不能完成同等操作。建议使用原生按钮或补全语义与键盘事件，并避免刷新导致焦点丢失。
8. **历史配置与显示不一致。** historyLimit 可设置 0–100，界面 :181 固定只显示 5 条。建议默认显示 5 条并提供“查看更多”，展示真实保留条数，或统一配置语义。
9. **历史任务终端关闭后无反馈。** 普通终端历史点击只执行可选的 info?.terminal.show()，查不到终端就静默无动作。建议标注“终端已关闭”，提供打开目录/查看保留输出的明确动作。
10. **窄面板适配。** 三个统计块、完整状态标签、耗时同时存在时容易挤压任务名。建议在窄宽度时压缩统计条、将耗时移到第二行。需要实际在窄/宽面板、浅/深主题、高缩放下验收，当前没有据此宣称已出现视觉溢出。

建议视觉结构（示意，不是已实现界面）：

```text
任务                         已同步
进行中 2       等待你 1       异常 0

⌄ Codex · 3
  修复终端跳转                 等待批准
  执行命令需要你的确认          2分18秒

  优化任务列表                 进行中
  正在修改文件                 1分05秒

⌄ 终端 · 2
› 最近完成 · 4
```

悬浮：任务完整标题 → 状态与耗时 → 等待原因/阶段概括/可用的最近回复 → 目录与同步时间。长文本折行、限制高度并可滚动，不增加每个条目的折叠开关。完成项优先给简短结果，失败项优先给失败原因。

## Codex 数据与性能

- **阶段概括不是原始回复。** 当前只请求 thread/list 与 thread/turns/list 的 summary，TurnItem 类型只声明 type/status。“正在修改文件”等是本地映射。状态来源确实是 Codex，但不能称为原始回答内容。若增加“最近回复”，先确认本机协议支持的字段与分页，再取最近一条公开 agentMessage，截取约 120–200 字；没有返回时隐藏。不展示内部推理，不编造任务完成百分比。
- **分开三种时间。** thread.updatedAt 是会话更新时间，turn.startedAt 是本轮开始时间，lastSuccessfulSync 应由插件记录。现有卡片“更新于”使用会话时间，不能证明连接刚刚成功。
- **轮询成本。** 每 3 秒读一次 thread/list，并对每个选中任务读取最近 turn；已完成任务也重复读取。建议已完成任务按 updatedAt 缓存，活动任务有限并发轮询，隐藏面板降频，断线指数退避。当前未测量 CPU 或耗时，不能量化性能收益。
- **重复推送。** Dashboard 每秒扫描名称并发送完整状态，TerminalWatcher 同样每秒扫描。前端收到后才 JSON.stringify 去重。建议合并扫描，在扩展端比较快照后再推送，隐藏时暂停 Webview 推送。
- **分页和范围。** thread/list limit=100，但没有处理后续页；大量会话时可能遗漏。无 workspace 时也不限制 cwd。建议支持分页及清晰的“当前工作区/全部”范围，并在 UI 说明范围。
- **通知缺口。** Notifier 只收到终端 shell 命令完成事件；CodexMonitor 的状态转换没有接入通知。建议对 Codex turn 的 completed/failed/waitingOnApproval 转换做去重通知，避免每次轮询重复通知及首次加载历史时补发。

## 终端与连接稳定性

- **输出按 chunk 当行。** taskManager.ts:76 对每个 chunk 独立 splitOutputLines。模拟 `hel`、`lo\n` 会成为两行，影响最近输出。建议每个任务维护未完成行缓冲，按换行提交，结束时补交尾行；ANSI 跨 chunk 也需要缓冲。
- **Agent 误分类。** agentDetector.ts 正则匹配命令中的任意位置。模拟 `echo codex` 被识别成 Codex，`git add agent.ts` 被识别成 Agent。建议解析实际可执行程序，处理 env、路径及常见包装命令，避免扫描参数中的任意关键词。
- **命令结束关联。** TerminalWatcher 用终端 currentTaskId 处理结束事件，并等待输出 reader 完成。建议按 execution 对象关联 task，设置有界的输出收尾时间，避免异常流不结束时长期不更新状态。此项为代码风险，未在真实 shell 中复现。
- **连接清理确定有缺陷。** appServerClient.ts:218、226 先 handleDisconnect 清空 this.socket，再 this.socket?.destroy()，实际不会销毁旧 socket。模拟超大 frame 已复现，应先保存并销毁具体 socket。分片仅限制单帧，没有限制累计消息长度；建议增加总消息上限、握手头上限和 dispose 后禁止重连的标记。
- **长期映射清理。** terminalOrder、terminalActivity、codexTerminalBindings 没有完整的过期清理；关闭终端和淘汰任务后应清理无效项。

## 构建与交付

1. 当前终端 PATH 中没有 node/npm，因此没有完成源码的 TypeScript 全量编译检查。此前版本采用手工同步 dist 和重新封装 VSIX；这种流程容易使源码与安装包产生差异，应优先恢复标准构建。
2. package.json 的 package 只调用 vsce，没有 vscode:prepublish 编译钩子；dist 又被 Git 忽略。干净克隆后直接打包可能缺少入口或打入旧输出。建议打包前强制 clean + compile，并检查 VSIX 内入口与版本。
3. 仓库没有提交依赖锁文件，也没有 CI/自动回归检查。建议固定 Node 版本、提交 lockfile，通过 npm ci 编译和打包。用有意义的边界测试覆盖匹配、掉线、状态转换、流式输出与点击交互。
4. App Server initialize 中仍写死 version=1.2.3，与插件 1.2.6 不一致；从扩展元数据统一读取。
5. README 开发调试写 F5，但仓库没有 launch.json，干净克隆未必能按文档直接运行。应补可复现的 Extension Development Host 配置。
6. Unix socket 路径被写死，extensionKind=workspace。跨系统和 Remote SSH 时不能直接承诺连接到用户本机的 Codex 服务；需要明确支持范围，并展示当前扩展运行位置及连接诊断。

## 建议实施顺序与验收

第一批：恢复可靠构建；修复按目录误去重、兜底绑定不更新、断线清空和连接销毁；补对应回归测试。同目录并行任务不得消失，已有点击体验应继续有效，连接恢复不得重复任务。

第二批：统一计数、等待原因和语言；实现连接状态、卡片局部刷新、折叠记忆、键盘操作。核对真实 VS Code 中窄面板、长标题、悬浮停留、键盘导航和重载后的表现。

第三批：按协议能力提取最近回复、完成/等待通知、历史查看更多及轮询缓存。先确保内容来自正确会话和本轮任务，再逐步增加信息密度。

验证记录：通过 Node VM 对实际 dist 模块进行隔离模拟，复现了同目录误去重、兜底绑定锁定、轮询失败清空、chunk 断行、命令误分类、超大帧未销毁连接六类问题；没有连接或干预实际 Codex 任务。以上其他条目为静态代码检查结果或设计建议，均未声称已实测修复。
